数据截止：2026 年 9 月 6 日，北京时间。检索日期已通过本机 `date` 确认。范围：通用语言、推理、代码及以文本为输出的多模态模型。本文是技术研究，不涉及证券投资建议。

配套报告：[千亿参数模型、许可证与部署成本](</Users/linxuan/ai-berkshire/reports/大模型全景对比-20260906/02-千亿参数模型报告.md>)。

## 先读结论

选模型需要同时回答三个问题：任务能否完成、完成一次要花多少钱、能否合法地自行部署。参数量只能回答其中一部分。

截至本次检索，全球前沿产品已经包括 GPT-6 Astra、Claude Fable 5.1 / Opus 5、Gemini 3.8 Flash / 3.1 Pro Preview、Grok 4.6、Muse Spark 1.3；中国重点候选包括 DeepSeek-V4、Qwen3.8、Kimi K3、GLM-5.3、MiniMax M3。它们的“旗舰”含义不同：有的是能力上限，有的是厂商主推的生产模型，有的是可下载权重的最强产品。本报告将这几种定位分别写明，而不以型号中的数字大小排名。[OpenAI 模型页](https://developers.openai.com/api/docs/models/gpt-6-astra)、[Claude 产品矩阵](https://platform.claude.com/docs/en/models/overview)、[Google 模型目录](https://ai.google.dev/gemini-api/docs/models)、[Grok 模型目录](https://docs.x.ai/developers/models)、[Meta 产品页](https://ai.meta.com/llama/)。中国模型的逐项来源见下表。

最需要纠正的认知是：**权重能下载，不代表可以不受额外条件限制地商用。** Kimi K3、Qwen3.8-2.4T、GLM-5.3、MiniMax M3 都有自己的许可证；GLM-5.3-Flash 则是 MIT。同一家公司的不同代际、不同档位可能采用完全不同的许可。[Kimi K3 许可证](https://huggingface.co/moonshotai/Kimi-K3/blob/main/LICENSE)、[Qwen3.8 许可证](https://huggingface.co/Qwen/Qwen3.8-2.4T-A95B/blob/main/LICENSE)、[GLM-5.3 许可证](https://huggingface.co/zai-org/GLM-5.3/blob/main/LICENSE)、[MiniMax M3 许可证](https://huggingface.co/MiniMaxAI/MiniMax-M3/blob/main/LICENSE)、[GLM-5.3-Flash 许可证](https://huggingface.co/zai-org/GLM-5.3-Flash/blob/main/LICENSE)。

## 范围与判断方法

“所有旗舰”没有权威、固定的全集。本文覆盖 23 家主要厂商或研究组织的旗舰及必要的开放模型对照；同一权重的量化版、微调版和不同 API 日期快照通常合并。未覆盖所有地方性厂商、行业专用模型和实验室内部模型。图像生成、视频生成、语音合成、机器人模型不纳入同一排行榜，因其任务和计费单位不同。

表中的“优先评估用途”是基于模型设计、接口能力及公开评测作出的选型判断，不是本报告实际跑分。基础模型、聊天产品与执行工具的软件环境分别看待：模型会调用工具，不等于下载权重后就自动具备浏览器、联网搜索、文件管理或电脑控制功能。

开放程度采用以下明确口径：

| 标记 | 本文含义 | 能否自行部署 | 商用判断 |
|---|---|---|---|
| 闭源 | 未核实到公开模型权重，主要通过产品/API 提供 | 通常不能直接获得权重；企业特约另论 | 按服务合同 |
| 宽松许可开放权重 | 权重采用 MIT、Apache 2.0 等许可 | 可以，前提是算力与框架支持 | 通常允许，仍须履行许可证义务 |
| 附条件开放权重 | 自定义、社区或研究许可证 | 通常可以下载；可能要求申请 | 必须逐条看商业门槛、用途和再分发条款 |
| 受限预览 | 已发布或展示，但访问对象受限 | 不能据此认定权重开放 | 按准入及合同 |

这是一份**权重与许可证核查**，不是对每款模型是否满足完整“开源 AI 定义”的认证。完整开放还涉及训练代码、数据说明、修改和复现所需材料。MIT/Apache 权重本身不能证明整个训练过程可复现。[OSI 开源 AI 定义](https://opensource.org/ai/open-source-ai-definition)。

## 到底谁更强：保留可比条件，才能读懂分数

本次没有运行付费 API 的实测。以下引用评测机构自己的原始分析，以及厂商公布的原始评测，明确区分两种证据。

### 独立评测快照：2026 年 9 月 3 日

Artificial Analysis 当日的 Astra 专题给出了下列结果。Intelligence Index 和 Coding Agent Index 是两套指标，**两列之间不可比大小**。代码列评估的是模型搭配具体工具环境的系统能力。

| 模型及评测设置 | Intelligence Index | Coding Agent Index | 能说明什么 |
|---|---|---|---|
| Claude Fable 5.1，最高推理档，含 fallback 条件 | 66 | 70，Claude Code | 该快照中领先；需保留 fallback 条件 |
| GPT-6 Astra，max | 61 | 67，Codex | 在代码执行系统中的竞争力强；通用指数并未与前代明显拉开 |
| GPT-5.6 Sol，max | 61 | 65，Codex | 是比较成本与效果的重要基准 |
| Claude Opus 5、Fable 5、Muse Spark 1.3 | 本表不从文字估计 | 文中描述约在 67 同一水平，运行环境各异 | 只能支持同一能力区间，不能据此强行分出第一至第四 |

数据来自同一篇[Artificial Analysis 原始评测文章](https://artificialanalysis.ai/articles/benchmarking-gpt-6-astra)。最后一行没有伪造精确小数。9 月 6 日动态排行榜可能增加测试或调整指数，不能与这份 9 月 3 日快照直接拼接。

由此作出的判断：**追求复杂任务上限，可把 Fable 5.1 与 Astra 放在第一轮实测；考虑价格时，Opus 5、Sol 及其他候选仍然有意义。**“更新”“输入价更高”都不足以证明每一种任务更划算。

### 中国开放模型：以任务为单位比较

Z.ai 公布的 GLM-5.3 评测表中，Terminal-Bench 2.1 的分数为 GLM-5.3 88.2、Kimi K3 88.3、DeepSeek-V4-Pro-0813 87.9、Qwen3.8-Max 86.6；DeepSWE v1.1 分别为 66.9、67.5、62.7、56.6。这说明几款模型都值得进入长任务代码候选池，且在不同任务上的差距不同。[Z.ai 原始模型卡及评测脚注](https://huggingface.co/zai-org/GLM-5.3)。

**这些是厂商公布的数据，不是四款模型在本地统一环境下复测的结果。** 模型卡对各项基准使用了不同工具框架、时间预算及部分自定义修正，竞争模型的数字也可能转引各自最佳结果。不能拿 0.1 分差异宣称稳定领先，不能拿发布时的旧型号成绩代表今天的最新旗舰。

从工程用途看，Kimi K3 的原生视觉与长任务能力、GLM-5.3 的代码方向、DeepSeek-V4 的长上下文设计、Qwen 的多档位生态，分别构成候选理由；最终顺序应由你的中文资料、代码仓库与输出要求决定。

## 如何按场景选

以下为基于上述事实的选型建议，并非已完成你的业务实测。

| 需求 | 第一轮候选 | 决定胜负的指标 |
|---|---|---|
| 复杂代码与跨软件长任务 | Fable 5.1、Astra、Opus 5；开放侧 Kimi K3、GLM-5.3、DeepSeek-V4-Pro | 验收通过率、单次成功成本、需要人工接手次数 |
| 音频、视频、长文档一体理解 | Gemini 3.8 Flash / 3.1 Pro；再评估 Muse、Kimi 与 MiniMax 的对应接口 | 模态是否原生支持、时间定位准确率、表格/图形读取错误率 |
| 中国业务的中文办公与产品集成 | Seed2.1、Hy3、Qwen、Kimi、ERNIE 5.1 | 真实中文资料、工具权限、引用可追溯性与价格 |
| 商业自托管，希望减少额外许可门槛 | DeepSeek-V4、Qwen3.5、GLM-5.3-Flash、Hy3、Command A+、K-EXAONE 2.0 | 正确许可证版本、部署框架、硬件、吞吐、业务成功率 |
| 尝试 100B 级本地推理 | gpt-oss-120b、Qwen3.5-122B、Nemotron 3 Super、Ling-2.6-flash | 可用内存和量化质量，不能只看激活参数 |
| 韩语或欧洲企业需求 | Solar Pro 3 / K-EXAONE 2.0；Mistral / Cohere | 目标语言表现、私有部署、许可证与交付支持 |

实际评估宜取一组固定的代表性任务，固定工具、数据、时间预算和验收标准，记录成功率、总费用及人工修改时间。涉及检索的回答还应记录引用是否真正支持原句。单看榜单、参数或每百万 tokens 价格，都不能代替这一步。
