# 千亿参数大模型：规模、开放程度与部署成本

数据截止：2026 年 9 月 6 日，北京时间。范围：总参数至少 100B 的通用语言、推理、代码及视觉语言模型；同一模型的量化版和部分日期快照合并。资料来自官方模型卡、许可证与原始论文。本报告为技术研究。

配套报告：[全球旗舰能力与价格对比](</Users/linxuan/ai-berkshire/reports/大模型全景对比-20260906/01-全球旗舰模型对比报告.md>)。

## 最重要的结论

**千亿参数并不等于每次都计算千亿参数，也不等于比小模型更强。** 当代很多大模型采用混合专家架构（MoE），权重总量决定存储规模，每次激活的参数只占其中一部分。与此同时，现代后训练、数据、工具与推理预算足以使参数较小的模型在特定任务中超过较大的模型。

**开源状态必须按具体模型及版本判断。** DeepSeek-V4、Qwen3.5、Hy3、Command A+、K-EXAONE 2.0 有较宽松的权重许可；Kimi K3、Qwen3.8-2.4T、GLM-5.3、MiniMax M3 等附有不同商业条件。更早的 DeepSeek-V3 初版也不能自动按后来 V3.1/V3.2 的 MIT 许可处理。逐项来源见以下清单。

本清单覆盖主要可核实产品、开放权重及历史研究模型，不声称穷尽全世界所有训练实验、合并模型与社区微调。没有公开参数的旗舰不会被猜测成“万亿模型”。

## 计数规则：先把 B、T 和激活参数分开

| 表达 | 换算或含义 |
|---|---|
| 1B 参数 | 10 亿参数 |
| 100B 参数 | 1,000 亿参数，即本文“千亿”门槛 |
| 1T 参数 | 1 万亿参数，即 1,000B |
| 235B-A22B | 总参数约 2,350 亿，每 token 激活约 220 亿 |
| 128B 稠密模型 | 每次前向传播使用基本全部主干参数；不是 MoE 式只选择少量专家 |
| 激活参数 | 每 token 调用的模型部分；它不是显存占用，也不是精确 FLOPs 或响应速度 |

本文主表优先采用开发者公布的模型规模。附加预测层（MTP）、视觉编码器、嵌入层及量化相关张量是否计入，不同来源可能不同，因此保留“约”“主干”“仓库张量统计”等标签。训练语料 tokens 数、上下文长度和参数个数是三件不同的事。

Grok-2 的权重确已公开，采用 Grok 2 Community License；网络常见“270B 总量 / 115B 激活”来自社区按结构计数，本次未把社区算术当作厂商正式参数披露，故列作补充而不放进精确排序表。[官方权重卡](https://huggingface.co/xai-org/grok-2)。Llama 4 Behemoth 等曾公开预告的超大模型，也不能仅凭发布演示就标成已经能下载。本次未完成其当前独立权重发布的确认，不列入可下载清单。

## 千亿模型究竟需要多大内存

如果所有参数均以相同精度保存，**仅权重**的理论体积为：

`参数个数 × 每个参数的位数 ÷ 8`。

下表为十进制 GB，1GB = 10^9 字节。BF16/FP16 为 2 字节，8 bit 为 1 字节，4 bit 为 0.5 字节。表中量化是假设，不保证每款模型都有对应精度的可用、等质量实现。

| 参数规模示例 | 16 bit 权重 GB | 8 bit 权重 GB | 4 bit 权重 GB |
|---|---:|---:|---:|
| 100B 门槛 | 200 | 100 | 50 |
| 117B，gpt-oss 主规模 | 234 | 117 | 58.5 |
| 122B | 244 | 122 | 61 |
| 196B | 392 | 196 | 98 |
| 320B | 640 | 320 | 160 |
| 397B | 794 | 397 | 198.5 |
| 428B | 856 | 428 | 214 |
| 671B | 1,342 | 671 | 335.5 |
| 753B 示例口径 | 1,506 | 753 | 376.5 |
| 1.02T | 2,040 | 1,020 | 510 |
| 1.6T | 3,200 | 1,600 | 800 |
| 2.4T | 4,800 | 2,400 | 1,200 |
| 2.8T | 5,600 | 2,800 | 1,400 |

以上已使用项目精确算术工具复核；不是采购配置。实际部署还要增加 KV cache 或线性注意力状态、量化 scale、激活、通信缓存、框架工作区与内存余量。不同 MoE 专家会在不同 token 被调用，**不能只按“激活 13B”给 284B 模型准备 13B 权重的显存**。也可以将部分权重放在 CPU 内存、磁盘或跨节点加载，但速度与并发会受内存带宽和互联影响。

例如，gpt-oss-120b 官方说明可以用原生量化方案运行在单块 80GB GPU 上；这不等于所有 120B 模型的所有精度、上下文与并发都能使用同一配置。Qwen3-235B 的模型卡则对约 1M 上下文给出约 1,000GB 总 GPU 内存的示例要求，说明缓存和运行配置的影响很大。[gpt-oss 模型卡](https://huggingface.co/openai/gpt-oss-120b)、[Qwen3 长上下文说明](https://huggingface.co/Qwen/Qwen3-235B-A22B-Instruct-2507)。

## 从参数报告得到的选择结论

如果主要通过 API 使用，优先比较任务成功率、费用和延迟；厂商没披露参数并不妨碍评估。若要自行部署，先选择许可证和硬件预算，再筛模型能力。想试千亿级，不必从 Kimi K3 或 Qwen3.8 这样的数万亿模型开始；117B 至 196B 的稀疏模型已经提供多种推理和工具任务路线。

**模型能力、参数规模、可下载性、商业授权，需要分别判断。** 它们有关联，但任何一个都不能替代另外三个。

## 核查与局限

参数来自开发者模型卡或原始论文；GLM-5.2/5.3 等另外检查了官方仓库元数据。许可证以具体权重仓库的正文或明确链接为准，不能只看网页上的“open source”宣传词。对需要账号接受条款的仓库，只读取公开页面与元数据，没有替用户接受许可。

本次没有运行模型推理、下载全部权重或验证训练可复现性。部分模型的精确激活量、最新 API 与公开权重对应关系仍未披露；这些空白已保留。历史条目用于理解规模演进，不能直接放入当代能力排行榜。完整核查记录见 [审计说明](</Users/linxuan/ai-berkshire/reports/大模型全景对比-20260906/03-核查记录.md>)。
